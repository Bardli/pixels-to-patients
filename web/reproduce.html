Reproduce it

Every number in this tour comes from one pipeline: LUNA25 screening‑CT nodule crops → the published JSC malignancy model → the seven attribution maps → their scores against the real nodule mask. No model is trained here; the checkpoint is the authors' own. Here is how to run it end to end.

Reproduce the experiment

1 · Environment

Dependencies are pinned in pyproject.toml and uv.lock:

shell1 · environment
uv sync

2 · Data

The fold‑3 validation split of FLARE‑AutoMSC Dataset005_LUNA25 — 1,289 screening‑CT nodule crops with malignancy labels. The dataset is gated on Hugging Face, so access is requested there; nothing is redistributed here:

shell2 · data
python scripts/download_luna25_fold3.py --fold 3

→ data/luna25/{imagesTr,labelsTr}/ · 2,578 files · 1,770 MB · per-file SHA-256 in artifacts/jsc/fold3_val_manifest.csv

3 · Model

No training step: this uses the published JSC fold‑3 checkpoint — the FLARE26 AutoMSC joint segmentation + classification baseline — laid out the way its official inference script expects:

path3 · model
artifacts/jsc/model/nnUNetCLSTrainerMTL__nnUNetPlans__3d_fullres/
├── dataset.json
├── plans.json                 # dataset_name Dataset005_LUNA25
└── fold_3/checkpoint_best.pth # 443,676,001 B · sha256 33ad8109…5968f

Gotcha: use the downloaded plans.json. The copy embedded in the checkpoint names the dataset Dataset009_LUNA25 while the folder on disk is Dataset005, and nnU‑Net resolves paths through that field.

4 · Attribute & score

Run all seven methods on the selected cases and score each heat-map against the real nodule mask. This writes the exact bundle this site reads:

shell4 · attribute + score
python scripts/jsc_web_export.py --device cuda \
  --cases 203125_1_19990102 207347_1_20010102 100438_5_20010102 \
          100471_3_20000102 134082_1_19990102

→ web/public/data/ · manifest.json · benchmark.json · model_graph.json · examples/<id>/

Each map is scored against the ground-truth mask with three metrics — the numbers you saw on the method pages and the compare board:

  • enrichment — the headline number. mass_in_gt ÷ the mask's volume fraction. A uniform heat-map scores exactly 1.0; above 1.0 means the heat really is concentrated on the lesion. Real nodules occupy 0.02–0.5% of the volume, so raw mass collapses toward zero and stops being comparable between a small nodule and a large one — enrichment is.
  • mass_in_gt — share of the attribution mass inside the mask. Kept as a raw diagnostic, no longer headlined.
  • inside_outside_ratio — mean heat inside the mask ÷ mean heat outside
  • pointing_acc — whether the single hottest voxel lands inside the mask
  • seg_dice — Dice of the model's own predicted nodule mask against ground truth. JSC segments as well as classifies, so its explicit output is an independent check on where it thinks the lesion is — something a classifier-only model cannot offer.

Deliberate deviations from the official inference script, each of which would otherwise corrupt the attribution: test‑time augmentation is off (mirroring averages eight flipped branches, so gradients would live in flipped coordinate frames); the network runs in eval(), not the script's .train(), whose Dropout(0.5) makes every run non‑reproducible; geometric resampling is skipped, because LUNA25 ships pre‑cropped to the model's exact (64,128,128) patch and resampling would put image and mask in different frames; and TF32 is disabled so CUDA stays numerically comparable to CPU.

Provenance

Every run hashes the SHA-256 of the checkpoint, the data cache, and uv.lock, together with the git commit that produced it — so any number in this tour traces back to the exact inputs that made it. No figure is hand-drawn. Frozen schema: DATA_CONTRACT.md.

Rebuild this website (optional)

This site is just a static view of that experiment. To regenerate its data bundle and preview it locally: uv run gradcam-repro web-export --data … --checkpoint … --out web/public/data, then serve web/ over http (e.g. python -m http.server) — opening index.html via file:// blocks the data fetch().

Background

An implementation-first tour of attribution methods for medical-imaging CNNs, built for the MICCAI Educational Challenge 2026 ("From Pixels to Patients").

The task

This tour runs the seven attribution methods against a published medical model — the JSC FLARE26 AutoMSC joint segmentation + classification baseline — on LUNA25 screening‑CT nodule crops, and scores every heat‑map against the real nodule segmentation mask rather than a hand‑drawn region of interest. Nothing here is trained for the occasion: the checkpoint is the authors' own fold‑3 release, whose reported validation AUROC is 0.8875.

Why it matters: a model can be right for the wrong reason. A classifier can reach high accuracy while keying off scanner artifacts, patient positioning, or image borders instead of the lesion itself. Attribution, checked against honest quantitative metrics rather than eyeballed heat‑maps, is how you find out whether the network actually localises the nodule. Because JSC also segments, its own predicted mask gives a second, independent read on where it thinks the lesion is.
