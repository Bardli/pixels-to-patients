Grad-CAM

Weight each feature-map channel by how strongly its average gradient pushes the target class, sum the weighted channels, keep the positive part, and upsample. The canonical class-discriminative heat-map.

How it works

Grad-CAM asks one question of a trained network: which feature-map channels mattered for this class, and where were they active? It answers with a single backward pass.

The math

αkc = GAP( ∂yc / ∂Ak )  — average-pool the gradient over the volume
Lc = ReLU( Σk αkc · Ak )  — weighted sum of channels, keep positive
heat = trilinear-upsample( Lc → input size )

The implementation

The real function from the codebase — nothing hidden. The CAM is tapped at stage2, a 16-channel feature volume.

src/gradcam_repro/attribution.pygradcam()
def gradcam(model, x, target=None, layer="stage2", normalize=True):
    model.eval()
    model.zero_grad(set_to_none=True)
    logits, activation = _cam_forward(model, x, layer)   # activation.retain_grad()
    score_for_target(logits, target).backward()          # one backward pass
    gradients = activation.grad                           # dyc / dA^k
    weights = gradients.mean(dim=(2, 3, 4), keepdim=True) # a_k^c = GAP(grad)
    cam = (weights * activation).sum(dim=1, keepdim=True).clamp_min(0)  # ReLU
    cam = upsample_to_input(cam, x)                       # trilinear
    return normalize_map(cam) if normalize else cam

Gotchas that make it work

  1. Gradients are global-average-pooled over the whole 3D volume to get one weight per channel — the core CAM assumption that a channel's importance is spatially uniform.
  2. ReLU comes after the weighted sum, not before. It keeps only evidence for the target class, which is why Grad-CAM maps look "positive".
  3. Tapped at stage2, so the raw map is at feature-volume resolution, then trilinearly upsampled. The heat-map is inherently coarse — a property of where you tap.
  4. activation.retain_grad() is mandatory — stage2 is a non-leaf tensor, so without it activation.grad is None.
