Grad-CAM

Weight each feature-map channel by how strongly its average gradient pushes the target class, sum the weighted channels, keep the positive part, and upsample. The canonical class-discriminative heat-map.

How it works

Grad-CAM asks one question of a trained network: which feature-map channels mattered for this class, and where were they active? It answers with a single backward pass.

The math

αkc = GAP ( ∂yc∂Ak ) average-pool the gradient over the volume
Lc = ReLU ( ∑k αkc ⁢ Ak ) weighted sum of channels, keep the positive part
heat = trilinear‑upsample ( Lc ) upsample back to the input volume
  • Ak — the k-th feature-map channel at the conv_block tap (640 channels)
  • yc — the network's raw score for the target class c. JSC emits a single logit, so class 1 (malignant) uses +z and class 0 (benign) uses −z
  • ∂yc/∂Ak — gradient of that score w.r.t. channel k: how much each voxel of the channel moves the score
  • GAP — global-average pool: average over the whole D×H×W volume, giving one number per channel
  • αkc — the resulting weight for channel k: how important it is for class c
  • Σk — sum over all channels k
  • ReLU — keep positives, zero the rest (only evidence for the class)
  • Lc — the low-resolution class-c localization map (the raw CAM)
  • trilinear-upsample — resize Lc from the feature grid back up to the input volume size

The implementation

Verbatim from the codebase. The CAM is tapped at conv_block, the 640-channel feature volume the classification head pools over.

scripts/gradcam3d_viz.py_compute_truegradcam()
def _compute_truegradcam(model, x_batch, stages, stage_names, target_shape,
                         target_cls, extract_logits_fn, pid):
    """True Grad-CAM via MONAI, with inversion fix."""
    raw = {}
    for sname, stage_mod in zip(stage_names, stages):
        wrapped = _MonaiGradCamWrapper(model, stage_mod, extract_logits_fn)
        wrapped = wrapped.to(x_batch.device)
        wrapped.eval()
        tl_name = _get_module_name(wrapped, stage_mod)
        cam = GradCAM(nn_module=wrapped, target_layers=[tl_name])
        # MONAI's default_normalizer maps (min,max)->(1,0), inverting the map.
        cam_t = cam(x_batch, class_idx=target_cls)
        if cam_t.ndim == 5:
            cam_t = cam_t[:, 0]
        att = cam_t[0].detach().cpu().numpy().astype(np.float32)
        att = 1.0 - att                       # undo MONAI inversion
        att = _upsample_to(att, target_shape) # (16,16,16) -> (64,128,128)
        raw[sname] = att
    return raw

The shared code

Every method here builds on two pieces of shared code. First, the published JSC network is wrapped so attribution can drive its own forward and backward pass. The official inference script is gradient-free at three nested levels: @torch.inference_mode() wraps the predict, sliding-window and mirror paths. Tensors made inside it can never re-enter autograd, so the forward pass has to be re-run rather than patched:

scripts/jsc_gradcam.pyJSCAdapter
class JSCAdapter(torch.nn.Module):
    """JSC network as forward(x) -> (seg_logits, cls_logit).

    A plain nn.Module with no inference_mode in its call path, so
    run_gradcam can drive forward/backward itself.
    """
    def __init__(self, network):
        super().__init__()
        self.network = network
        # CAM tap: conv_block output, (1, 640, z/4, y/8, x/8)
        self.conv_block = network.conv_block

    def forward(self, x):
        return self.network(x)

Second, JSC's head emits a single logit rather than one score per class, which breaks the logits[:, class_idx] convention every method uses. Two helpers reconcile it. Get the sign wrong here and every malignant case's heat-map silently inverts:

scripts/gradcam3d_viz.pysingle-logit scaffold
def _as_two_column(logits):
    """Single logit z -> [-z, +z]. Column 1 is evidence FOR malignant,
    column 0 its negation. Differentiable, so gradients are unaffected."""
    if logits.ndim == 2 and logits.shape[1] == 1:
        return torch.cat([-logits, logits], dim=1)
    return logits

def _pick_target_class(logits, user_target_class):
    if logits.shape[1] == 1:
        # target_class == -1 means "explain the predicted class", so it must
        # follow the prediction: logit > 0 is class 1. Hard-mapping -1 to
        # class 0 here would invert every positive case's heat-map, because
        # the class-0 attribution is the negation of the class-1 attribution.
        if user_target_class == -1:
            cls = 1 if logits[0, 0].item() > 0 else 0
        else:
            cls = int(user_target_class)
        score = logits[0, 0] if cls == 1 else -logits[0, 0]
        return cls, score
    cls = (int(torch.argmax(logits[0]).item())
           if user_target_class == -1 else int(user_target_class))
    return cls, logits[0, cls]

The computation, step by step

Below, watch Grad-CAM run end to end on a real case.

  1. A CT patch enters the network. One 64×128×128 screening-CT nodule crop, CT-normalised with the plans statistics. The classifier must decide: malignant or benign. x ∈ ℝ^(1 × 64 × 128 × 128)
  2. Forward pass → encoder, FPN, one tap. The PlainConvUNet encoder runs six stages (32→320 channels) and the FPN fuses the last three skips back to a single 320-channel volume, which conv_block lifts to 640. Grad-CAM taps that output. A = conv_block(x) ∈ ℝ^(640 × 16 × 16 × 16)
  3. Backward pass → one weight per channel. A single backward pass from the target logit gives ∂yᶜ/∂Aᵏ. Average each channel's gradient over the volume → a scalar importance weight αₖ. (Computed live in the notebook.) αₖᶜ = GAP( ∂yᶜ / ∂Aᵏ )
  4. Weighted sum, ReLU, upsample. Weight the channels, sum them, keep the positive part, and trilinearly upsample back to the input grid. This is the raw Grad-CAM heat-map. Lᶜ = Up( ReLU( Σₖ αₖᶜ Aᵏ ) )
  5. Overlay to localise. Laid over the CT, the heat-map shows where the network's evidence for the class lives, hopefully on the lesion. Each method page scores whether it does, against the nodule mask. read-out = CT ⊕ heat

Gotchas that make it work

  1. Gradients are global-average-pooled over the whole 3D volume to get one weight per channel. That is the core CAM assumption: a channel's importance is spatially uniform.
  2. ReLU comes after the weighted sum, not before. It keeps only evidence for the target class, which is why Grad-CAM maps look "positive".
  3. Tapped at conv_block, so the raw map is 16×16×16 and is trilinearly upsampled 8× in-plane to 64×128×128. The heat-map is inherently coarse, a property of where you tap.
  4. The forward pass must be re-run under enable_grad(). The official inference path is wrapped in @torch.inference_mode() at three levels, and tensors made inside it can never re-enter autograd, so there is no gradient to hook after the fact.
